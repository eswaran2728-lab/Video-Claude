# Variants and publishing

Create variants from a locked, approved base timeline. Preserve the base and increment version IDs. Change one primary variable per experiment: opening line, opening image, caption treatment, pacing or title. Keep the source facts and call to action consistent. Use actual frame-rate and duration changes only when they preserve natural speech and meaning. Maintain a variant manifest with parent version, changed variable, output path and notes.

Do not claim that every platform or account supports trial reels or scheduling. Check the current connected platform API and account permissions. An exported alternate reel is a variant; it is not a posted platform trial reel. Preserve already-published versions when making a new batch.

Before posting, obtain explicit user authorization for destination account, content version, caption and timing. Resolve timezone; for this user's default use Asia/Kuala_Lumpur unless told otherwise. Never place passwords, API tokens or session-bearing links in project files. Use a supported connected service, record its returned post ID and verify status. If there is no connector, deliver upload-ready files and posting instructions rather than claiming automatic publishing.
